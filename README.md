# OITERU（オイテル）

**学生証をかざすと、学内のトイレで生理用品を無料で受け取れる仕組みです。** 専用アプリは使いません。

担当になったら、まず先輩と **在庫を見る → 補充する → 管理画面に記録する** ところまでやってみましょう。当番はブラウザと実物の機械で始められます。

| いまやりたいこと | 開くページ |
| --- | --- |
| 引き継ぎを始める | [最初の 1 週間](START_HERE.md) |
| 当番で在庫を見る・補充する | [当番の手順](QUICK_START.md#daily) |
| 用品が出ない・子機がつながらない | [困ったときの確認と連絡](QUICK_START.md#help) |

## 使う人から見ると、3 ステップ

1. **登録する。** 初回は登録用のリーダーに学生証を置き、登録画面（`/register`）で「登録する」を押します。
2. **タッチする。** トイレの機械に学生証をかざします。
3. **受け取る。** 利用条件を満たしていれば、生理用品が 1 個出ます。

残り回数は、同じ登録用リーダーに学生証を置いて、利用状況の画面（`/usage`）で確認できます。登録と利用状況の確認に管理者ログインは不要です。担当者は管理画面（`/admin`）にログインして、在庫や故障の記録を見ます。実際に使う画面のアドレスとリーダーの場所は、先輩と [引き継ぎ票](docs/handover.md) で確認します。

## 中身は「親機」と「子機」

**子機は受け取り口です。** トイレにあり、学生証を読んで、モーターで生理用品を出します。

**親機は受付係です。** 学生証が登録されているか、まだ使える回数があるか、在庫があるかなどを確認します。担当者がブラウザで見る管理画面も親機が提供します。

ふだんは、子機が親機に「1 個出していい？」と聞きます。親機が許可すると受付番号が付き、子機がモーターを動かして「出せた／出せなかった」を報告します。受付番号で許可と結果を照らし合わせられます。親機とつながらないときの動作は [運用手順のスタンドアロンモード](docs/operations.md#スタンドアロンモード親機が止まっても子機が排出を続ける) にあります。

## まず覚える言葉は 5 つ

| 言葉 | 意味 |
| --- | --- |
| 親機（おやき） | 利用できるかを判断し、在庫や利用の記録を管理する PC |
| 子機（こき） | 学生証を読んで、生理用品を出す機械 |
| NFC | 学生証をかざして読み取る仕組み |
| データベース（DB） | 在庫や利用の記録などを保存する場所。オイテルでは MySQL 8 を使う |
| heartbeat（ハートビート） | 子機から親機への「動いているよ」という定期連絡 |

ほかの言葉を見かけたら [用語集](docs/glossary.md) で調べられます。

## 引き継ぐ仕事は 3 つ

- **見守る。** 管理画面で在庫と接続の状態を見ます。現地で補充し、追加した個数を記録します。最初は、先輩の横で一度見てから自分でやってみましょう。 [当番の手順](QUICK_START.md#daily)
- **直す。** 用品が出ないときや子機がつながらないときに、見える範囲で状態を確かめます。子機名と時刻を控え、故障を記録して担当者に連絡できれば十分です。 [困ったときの手順](QUICK_START.md#help)
- **良くする。** 興味があれば、自分の PC でテストを動かすところから始めます。 [開発の第一歩](#development)

質問するときは「何をしようとしたか」「何をしたか」「何が起きたか」の順に書くと伝わります。補充や故障の記録には、どの機械で、いつ、何をしたかを書きます。利用者の名前・学生証の番号・パスワードは記録やチャットに書かず、画面の写真でも隠してください。

## 開発してみたい人へ

最初は、自分の PC で **テスト（プログラムが想定どおり動くか自動で確かめるもの）** を実行します。実機も MySQL も用意せずに始められます。最後の集計に `passed` が出て、`failed` や `ERROR` がなければ成功です。MySQL が必要なテストは `skipped` と表示されます。Git と Python の準備から順に進められます。 [Windows・macOS・Linux の手順](docs/onboarding.md)

| フォルダ | 担当する仕事 |
| --- | --- |
| `app/api/` | 子機や画面から届いたリクエストを受け付けて返事をする |
| `app/services/` | 「このカードで 1 個出せるか」などのルールを判断する |
| `app/repositories/` | データベースから記録を読み出し、保存する |
| `unit/` | 子機の通信や、モーター・センサーの制御をする |
| `tests/` | プログラムの動作を自動で確認する |
| `docs/` | 設置、運用、開発の手順をまとめる |

コードを直す前に [開発時のルール](AGENTS.md) を読んでください。親機・子機の新規設置や復旧を担当するときは、作業に合った手順を開いてください。 [説明書の一覧](docs/README.md)

構成の参考資料は「オイテル引き継ぎオリエンテーション (1).pptx」です。
