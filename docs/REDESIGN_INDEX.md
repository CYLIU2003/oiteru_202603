# オイテル再設計の実装順

- [親機の業務画面](REDESIGN_OPERATIONS_DASHBOARD.md)
- [親機・子機連携](REDESIGN_DEVICE_COORDINATION.md)

## 共通方針

業務トップは「どの機器で何をすべきか」を示し、子機監視は判断に必要な根拠を示す。親機が受け取った heartbeat、端末の利用可否、NFC・モーター等の能力、設定適用の状態を分けて扱う。速報値を利用する画面には最終取得時刻と更新失敗を表示する。

## 段階と完了条件

1. 親機の業務トップを既存APIと既存画面への導線で組み直す。在庫切れや通信途絶から対象の画面へ移動できること、情報取得に失敗したときに古いデータと失敗を区別できることを確認する。
2. 監視APIに能力と設定の版を段階的に追加する。現行クライアントと併用し、親機で対象の3台がオンラインになり、非駆動の設定を送って各端末の適用応答を確認する。
3. UNO QでUSB NFCの実行時処理を検証する。モーターは実際の配線とMCU側のインターフェースを確定してから別工程で検証する。監視のオンライン表示を基準に払い出しを有効化しない。

本番反映前に、ステージングで通信断、親機再起動、子機再起動、適用応答の欠落を再現して確認する。対象の3台に展開する前に、段階ごとに親機と子機を直前の版に戻せることを確認する。
