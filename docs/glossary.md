# 用語集

説明書に出てくる言葉を、プログラミングの授業の途中でもわかるように説明します。
**最初の 1 週間は「まずここだけ」で十分です。** ほかは、説明書で出会ったときに調べてください。
入口は [START_HERE.md](../START_HERE.md) です。

## まずここだけ（当番で使う言葉）

| 言葉 | ひとことで | OITERU では |
| --- | --- | --- |
| 親機（おやき） | 受付の係をする PC | 研究室の Linux PC `hirameki-3`。名簿・在庫・記録を持ち、「出してよいか」を決める |
| 子機（こき） | 受け取り口の機械 | トイレにある Raspberry Pi。カードを読み、モーターで生理用品を出す。`rpi1`、`rpi2` など |
| NFC・カードリーダー | カードをかざして読む仕組みと、その読み取り機 | 学生証を読む。親機には登録用、子機には受け取り用のリーダーがある |
| 管理画面 | 担当者だけが使う Web ページ | URL の最後が `/admin`。ログインして在庫や故障を記録する |
| ログイン・ログアウト | 自分だと証明して入る・出る | 共有 PC では作業の最後に必ずログアウトする |
| 在庫操作 | 在庫の数を変えた記録 | 「補充」「在庫修正」「廃棄」の 3 種類。補充の数量は**追加した数**（合計ではない） |
| 故障チケット | 故障 1 件ぶんの記録カード | 「受付 → 対応中 → 復旧確認 → 完了」と進める |
| heartbeat（ハートビート） | 「動いているよ」という定期連絡 | 子機が親機へ 30 秒ごとに送る。60 秒以上届かないと「heartbeat 超過」に出る |
| オンライン・オフライン | 通信がつながっている・いない | 子機一覧の「接続状態」がオフライン、または運用管理の「heartbeat 超過」に名前があれば、子機の電源や通信を疑う |
| スタンドアロンモード | 親機が止まっても子機だけで動く仕組み | カード 1 枚につき 1 個まで。親機が戻ると記録を自動で送る |
| URL | Web ページの住所 | `https://…/admin` のような文字列。ブラウザの上の欄に入れる |

## 機械とネットワーク

| 言葉 | ひとことで | OITERU では |
| --- | --- | --- |
| Raspberry Pi（ラズパイ） | 手のひらサイズの小さな PC | 子機の中身。Linux が動いている |
| Linux・Ubuntu・Debian | Windows や macOS の仲間の OS | 親機は Ubuntu、子機は Debian（Raspberry Pi OS）を使う |
| SSH | 別の PC の黒い画面に、ネット越しに入る方法 | `ssh hirameki-3` で親機に入る。**本番の機械に入るときは先輩と一緒に** |
| Tailscale | 学外からでも研究室の機械につなげる仕組み（VPN） | 親機と子機はこれでつながっている。ときどき追加の認証を求められる |
| IP アドレス | ネットワーク上の機械の番号 | 子機を承認するとき、画面の IP と実機が合っているかを見る |
| HTTP・HTTPS | Web の通信方法。S が付くと暗号化される | 本番の運用は HTTPS が原則 |

## 黒い画面（ターミナル）

| 言葉 | ひとことで | OITERU では |
| --- | --- | --- |
| ターミナル・PowerShell | 文字でコンピューターに命令する画面 | Windows では PowerShell、Mac・Linux ではターミナルを使う |
| コマンド | ターミナルに打つ命令 | 説明書の灰色の枠の中。**1 行ずつ**貼って Enter |
| `cd` | フォルダを移動するコマンド | `cd ~/Desktop/oiteru_202603` で、プロジェクトのフォルダへ移動する |
| フォルダの場所（パス） | ファイルの住所 | プロジェクトは各機械のデスクトップにある。親機は `~/デスクトップ/oiteru_202603`、子機は `~/Desktop/oiteru_202603` |
| `sudo` | 管理者の権限でコマンドを実行する | 機械の設定を変えられるので、**付いているコマンドは先輩と一緒に**打つ |
| パスワードが表示されない | 入力した文字が画面に出ないこと | 故障ではない。見えなくても打って Enter を押す |
| Ctrl + C | 動いているコマンドを止めるキー | ログを見るのをやめるときに使う。親機や子機は止まらない |
| ログ | プログラムが書く日記 | 「いつ・何が起きたか」が残る。困ったときに先輩が読む |
| systemd（システムディー） | Linux で、プログラムを自動で起動・再起動する係 | 親機（`oiteru-parent`）と rpi1 の子機（`oiteru-unit`）は、これで自動的に動いている |
| tmux（ティーマックス） | SSH を切っても動き続ける作業画面 | 子機を手動で起動するときなどに使う |
| 文字化け・UTF-8 | 文字の決まりが合わず、文字が崩れること。UTF-8 は世界標準の決まり | 3 台とも UTF-8 にそろえてある（`scripts/setup_terminal_utf8.sh`） |

## プログラム

| 言葉 | ひとことで | OITERU では |
| --- | --- | --- |
| Python | プログラミング言語 | OITERU は Python で書かれている。3.12 以上を使う |
| `.venv`（仮想環境） | このプロジェクト専用の Python の部屋 | 必要な部品を、ほかのプロジェクトと混ぜずに入れておく場所 |
| pip・パッケージ | Python の部品と、その取り寄せ係 | `pip install -r requirements-dev.txt` で必要な部品をまとめて入れる |
| テスト・pytest | プログラムが壊れていないかを自動で確かめる仕組み | 結果に `passed` が出れば成功。`skipped` は今回は試さなかったもの |
| Git | ファイルの変更履歴を残す道具 | いつ・誰が・何を変えたかを記録する |
| GitHub | Git の記録をネットに置く場所 | `github.com/CYLIU2003/oiteru_202603` がこのプロジェクトの置き場所 |
| `git clone` | GitHub からまるごとコピーする | 最初に 1 回だけ使う |
| `git pull` | GitHub の新しい変更を取り込む | 機械のプログラムを最新にするときに使う |
| ブランチ・PR（プルリクエスト） | 変更を本流に入れる前の下書きと、その確認依頼 | 変更は PR で確認してから `main` に入れる |
| データベース（DB）・MySQL | データを表の形で保存する箱と、その種類 | 名簿・在庫・記録を MySQL 8 に保存している |
| migration（マイグレーション） | データベースの表の形を、順番どおりに変える手順 | 親機が起動するときに自動で実行される |
| `.env` | 親機の秘密の設定ファイル | パスワードや鍵が入っている。**開かない・人に送らない** |
| `config.json` | 子機の設定ファイル | 子機の名前やモーターの種類が入っている |
| API | プログラム同士が話すための窓口 | 子機は親機の API に「出してよいか」を聞く |
| `event_id`（受付番号） | 1 回の排出につく番号 | 「許可した」と「出せた」を結び付けて、二重に出ないようにする |
