検証環境は Linux、Python 3.14.4、MySQL 8.4.11 です。CI は Python 3.12 系です。
作業環境の `.env`・実 DB・カードデータは検証用コピーに持ち込んでいません。
一時 DB は実証で使う MySQL サービスとは別プロセスで動かし、検証後に停止しました。

## 今回見つけて直したこと

- 当番向けの QUICK_START が設置・保守も含め約 600 行あったため、当番の手順を約 180 行にし、開発と設置を別の正本へ整理した。
- 管理画面の補充数は合計数ではなく追加数であること、保存が不明なときに履歴を先に見ることを具体例で示した。
- 設定ファイルのコピー元を `config.example.json` に統一し、現在は使わない設定ウィザード等を削除した。
- 古い説明に残っていた tmux / systemd、HTTP / HTTPS、固定パスの混在を整理した。
- 標準の DB ユーザー権限でバックアップするとテーブルスペース取得の権限エラーが出たため、`--no-tablespaces` を追加した。

バックアップの回帰テストは [test_backup_mysql.py](../tests/test_backup_mysql.py) です。
MySQL テストを有効にした CI でも、必要なコマンドラインツールがあれば実行されます。

## 削除したファイルの根拠

現行コード・標準手順・CI の参照を調べ、旧ファイル 71 個を削除しました。
別途、重複していた設定案内を [configuration.md](configuration.md) に移して書き直しています。

| 種類 | 削除理由 | 現在の入口 |
| --- | --- | --- |
| 旧 Docker・SQLite・launcher・一時診断の 63 ファイル | 標準構成から未参照。古い認証、パス、DB 前提が混在 | [旧方式の履歴を調べる方法](../legacy/README.md) |
| 旧設定ウィザード 2 ファイル、重複・従親機用 JSON 2 ファイル | 固定 IP・古い配線・現在読まれない DB 設定などを生成 | [設定ファイル](configuration.md) |
| 特定 Windows PC 用の起動・NFC スクリプト 2 ファイル | 固定ユーザーパス、異なる WSL の前提、カード識別子の表示 | [WSL の検証手順](card_reader_windows.md) |
| 重複 Gunicorn 設定 1 ファイル | 標準サービスから未参照で、共通 bootstrap を通さない起動例を含む | ルートの `gunicorn.conf.py` と `wsgi.py` |
| 子機の重複セットアップ説明 1 ファイル | 親機の起動方式などに古い案内が残る | [初回セットアップ](setup.md) |

デザイン検証に使う `package.json` / `package-lock.json`、画面で使う画像・フォントは、用途があるため保持しています。
実 DB、ログ、バックアップ、秘密設定、参照元の PowerPoint を不要物として削除していません。
